# Đánh giá và nghiệm thu UC-04: Multi-Step Feature & Resume

## 1. Mục tiêu
UC-04 đánh giá khả năng thực hiện tính năng nhiều bước (multi-step feature implementation) trên repository mục tiêu TinyDB với:
- Graph `/feature`: Lập kế hoạch 3–7 bước, phê duyệt người dùng, thực thi từng bước với fail-closed verifier.
- Khôi phục sau sự cố (`/resume`): Sử dụng checkpointer SQLite (`checkpoints.db`) và task state (`task_state.json`), bảo đảm không chạy lại các bước đã hoàn thành.
- Tự động nén ngữ cảnh (`compaction`): Nén khi token vượt ngưỡng 60% context window, bảo đảm đủ 5 đề mục và giữ nguyên tiêu chí chấp nhận (`acceptance criteria`).
- Bộ nhớ dài hạn theo repository (`memory`): Lưu trữ và kế thừa quy ước lập trình qua các phiên làm việc trong system prompt.

### Sơ đồ graph `/feature`

```text
plan (3-7 bước) -> confirm người dùng -> doing ──► verify (fail-closed) ──┬─► doing (bước kế)
      │                                   ▲                              │
      │                                   └── test đỏ, còn ngân sách ────┤
      ├─ read-only: không snapshot, không sửa file                      └─► report
      │
      ├─ ngắt giữa chừng (Ctrl+C / AbortSignal)
      │     -> task_state.json + checkpoints.db giữ bước đã xong
      │     -> /resume đọc lại state, chỉ chạy bước còn thiếu
      │
      ├─ context > 60% -> /compact nén thành 5 đề mục, giữ nguyên acceptance criteria
      └─ /memory: quy ước dự án lưu theo workspace, nạp lại vào system prompt phiên sau
```

## 2. Danh sách Feature kiểm thử
| Mã | Tính năng | Yêu cầu tệp thay đổi | Acceptance test |
|---|---|---|---|
| `feat-01` | `Table.count_where` & `TinyDB.count_where` | ≥ 3 file (`table.py`, `database.py`, `__init__.py`) | Đếm tài liệu khớp query không dựng toàn bộ mảng |
| `feat-02` | Tham số `limit` cho `search()` | ≥ 3 file (`table.py`, `database.py`, `__init__.py`) | Giới hạn số lượng kết quả trả về, hỗ trợ limit ≤ 0 và limit=None |
| `feat-03` | `ReadOnlyMiddleware` | ≥ 3 file (`middlewares.py`, `__init__.py`, `storages.py`) | Cho phép đọc bình thường, chặn mọi thao tác ghi bằng `PermissionError` |

## 3. Các ca đánh giá (5 cases)
1. **`uc04-straight`**: Thực hiện `feat-01` một lèo từ đầu đến cuối. Đạt khi acceptance test pass, 0 regression trên 218 test TinyDB, và sửa ≥ 3 file.
2. **`uc04-resume-1`**: Thực hiện `feat-02`, ngắt sau bước 2 và gọi `resumeTask`. Đạt khi các bước 1–2 không bị chạy lại, bước 3–4 hoàn tất, acceptance test pass và 0 regression.
3. **`uc04-resume-2`**: Thực hiện `feat-03`, ngắt 2 lần liên tiếp và khôi phục. Đạt khi các bước đã xong không chạy lại, hoàn tất toàn bộ và acceptance test pass.
4. **`uc04-compaction`**: Kích hoạt compaction với task state. Đạt khi đủ 5 đề mục (`Goal`, `Constraints`, `Completed steps`, `Current state`, `Open risks and next step`) và `acceptance criteria` được bảo toàn nguyên văn.
5. **`uc04-memory`**: Phiên 1 ghi quy ước vào `addMemory`, phiên 2 kiểm tra `buildSystemPrompt` chứa `# Project memory` và agent tuân thủ quy ước.

## 4. Ngưỡng chấp nhận (Acceptance Gate)
- `featurePassRate ≥ 2/3` (ít nhất 2 trên 3 feature vượt qua kiểm thử chấp nhận và không hồi quy).
- `resumeOk = 1` (cả 2 kịch bản crash/resume hoạt động chính xác, không lặp bước).
- `compactionOk = 1` (đủ 5 section và bảo toàn acceptance).
- `memoryOk = 1` (kế thừa quy ước vào system prompt thành công).
